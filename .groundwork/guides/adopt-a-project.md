### Adopt a project

Start with an existing project that has its own instructions and ignore rules. The agent runs `groundwork init` when setup is missing. Normal project commands (`init`, `verify`, guide/report views and `map`) call `prepareProject` before loading configuration and guides. Base configuration becomes `.groundwork/verify.d/` fragments with IDs, bindings and check order preserved. Authored `VERIFY.md` content becomes active guides, with shared context reached through a small marked bootstrap. Affected guide and `AGENTS.md` references follow the conversion; superseded bases, guides and ignore archives are removed. A second command leaves the converted metadata unchanged. Configuration and portal reads remain pure.

The agent resolves conflicting definitions or project-specific path repairs using repository context and continues the task. Exercise a migrated check through its real command to establish that moved inputs still work. Generated `.groundwork/runs`, `.verify/runs` and latest pointers move to external storage before their originals are removed. Historical reports retain their identity and do not become reusable receipts.

Reusable Groundwork-owned helpers and supporting configs belong in `.groundwork/scripts/` and `.groundwork/config/`. Plans, task notes and scratch files live in ignored subpaths. Runs and receipts use `GROUNDWORK_STATE_HOME`, otherwise `$XDG_STATE_HOME/groundwork`, defaulting to `~/.local/state/groundwork`. Worktrees share a repository evidence namespace with workspace-specific latest pointers. Commands run from the project root, even when invoked inside `.groundwork/`. Changes to reusable verification inputs invalidate saved applicability; runtime files do not.
