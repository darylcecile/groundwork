### Final PR verification

Consult [local-first verification](../decisions/local-first-verification.md) for the record/publication boundary. Every local save keeps authoritative `result.json` and derived `report.md`, whether or not a PR exists. `groundwork publish pr [number-or-url] --run <id>` shares an explicit run using a PR artifact when available, otherwise a readable comment with hidden versioned JSON. Omit the PR to use the current branch. Publication reassesses source/PR matching and coverage/review gates while preserving the original run; identical content committed and pushed after a dirty run can match.

`groundwork view pr [number-or-url]` shows recorded outcomes and current-head matching, without fresh local-environment reassessment; a URL also works outside an adopted repository. Historical records remain visible. The latest current-head record determines exit `0` (passed), `1` (failed), or `2` (incomplete or absent). Remote accounts are review context, not automatically reusable receipts.

The reusable workflow is `.github/workflows/verify.yml`; its runtime and prompt live in `pr-verification/`. It prepares metadata before loading configuration and capturing source, runs the importing project's selected checks, then uses the agent for remaining verification gaps, including unsatisfied review obligations, captures evidence, and updates the importing PR's verification comment and status. Callers grant `pull-requests: write` and `statuses: write`. Valid exact-ID review evidence can satisfy a review obligation without another agent pass. Local evidence defaults to the external store; CI supplies runner-temporary output. An optional archive does not gate a valid text report; missing required observations still prevent a pass. A later agent pass cannot erase a failed check.
